# MASTER PROJECT PROMPT
# AI SOFTWARE HOUSE — Autonomous AI Company Operating System

## 1. YOUR ROLE

Act as a Principal Software Architect, AI Systems Engineer, Multi-Agent Systems Engineer, Senior Full-Stack Developer, DevOps Engineer, and Security Engineer.

Build a real, extensible AI Company Operating System for an IT Solutions and Software House business.

This is NOT merely a chatbot, AI dashboard, or collection of independent AI agents.

The goal is to simulate and operate a software company in which AI employees have organizational positions, responsibilities, specialized skills, access permissions, persistent workspaces, assigned tasks, measurable deliverables, and collaboration workflows.

The human owner acts as CEO and retains authority over company strategy, budgets, high-risk decisions, and external commitments.

AI employees should perform actual work through authorized tools, not simply describe what they would do.

## 2. BUSINESS VISION

Build a virtual Software House that can:

- Receive software project requests from the CEO or customers.
- Analyze business requirements.
- Prepare proposals and project estimates.
- Evaluate feasibility, cost, risks, and expected profitability.
- Create project plans, milestones, and tasks.
- Assign tasks to suitable AI employees.
- Develop software through authorized coding tools.
- Review code and execute tests.
- Track progress, costs, blockers, and quality.
- Produce documentation and delivery packages.
- Manage internal operations, company knowledge, and performance.
- Improve workflows based on measurable results and human-approved feedback.

The architecture must support adding new departments, job positions, AI models, tools, and external integrations without rewriting the core platform.

## 4. AI EMPLOYEE MODEL

Each AI employee must have:

- Unique employee ID and display name.
- Job title, department, manager, and organizational level.
- Job description and responsibilities.
- Skills and supported task types.
- System instructions and behavioral constraints.
- Configurable AI model and provider.
- Authorized tools and permission scopes.
- Input and output schemas.
- Task queue and current assignments.
- Working memory and approved long-term knowledge.
- Work history and execution logs.
- Performance metrics and quality evaluation.
- Token usage, execution time, and cost records.
- Status: Available, Working, Waiting for Approval, Blocked, Failed, or Inactive.

Each employee must produce structured deliverables and report task status.

AI employees must not be able to grant themselves new permissions, rewrite their own security policies, or bypass approval requirements.

## 5. MULTI-AGENT ORCHESTRATION

Build a central Agent Orchestrator.

Responsibilities:

- Receive objectives from the CEO.
- Classify the request and identify the required departments.
- Create a structured execution plan.
- Break objectives into tasks and subtasks.
- Select agents according to skills, availability, permissions, cost, and workload.
- Track task dependencies.
- Dispatch tasks to authorized execution workers.
- Validate outputs against acceptance criteria.
- Route deliverables to reviewers or managers.
- Retry recoverable failures with configurable limits.
- Escalate blockers and ambiguous decisions.
- Request human approval when required.
- Track execution costs, timeouts, and resource limits.
- Persist state so interrupted workflows can resume safely.

Use explicit workflow states and durable task records.

Support sequential workflows, parallel tasks, approval gates, retries, cancellation, and recovery.

Prevent infinite delegation, circular task dependencies, uncontrolled agent-to-agent conversations, duplicate external actions, and runaway spending.

Agents may communicate through structured task assignments, messages, and deliverables. Do not rely exclusively on free-form conversations to coordinate work.

## 6. REAL WORK EXECUTION

Implement a controlled tool system.

Potential tools include:

- Read and search authorized project files.
- Create and edit files within approved workspaces.
- Run unit and integration tests.
- Run linting, formatting, and static analysis.
- Read Git status and diffs.
- Create branches and pull requests through authorized integrations.
- Query approved databases using restricted access.
- Generate documents and spreadsheets.
- Search approved internal knowledge.
- Access approved project management tools.
- Use email and calendar integrations when connected.
- Run containerized development and testing environments.

Every tool must declare:
- Tool identifier and version.
- Input and output schema.
- Required permissions.
- Execution timeout.
- Resource limits.
- Whether human approval is required.
- Audit and error-handling behavior.

Run untrusted code in isolated execution environments with restricted filesystem access, network access, credentials, CPU, memory, and execution time.

Never expose unrestricted host shell access or production credentials to AI agents by default.

An AI response alone must never be treated as proof that an action succeeded. Verify actual tool results.

## 7. SOFTWARE PROJECT DELIVERY WORKFLOW

Implement a reusable end-to-end software delivery workflow.

Stage 1: Lead Intake
- Record customer request, business objective, budget, deadlines, and constraints.
- Identify missing information.
- Ask for clarification when necessary.

Stage 2: Discovery and Analysis
- Generate business requirements.
- Produce user stories and acceptance criteria.
- Identify functional and non-functional requirements.
- Record assumptions, dependencies, and risks.

Stage 3: Proposal and Estimation
- Propose solution options.
- Estimate effort and operational cost.
- Calculate estimated gross margin and contingency.
- Produce proposal and statement of work drafts.
- Flag estimates that lack sufficient evidence.

Stage 4: Architecture and Planning
- Produce architecture diagrams and technical specifications.
- Design database schemas and API contracts.
- Define security requirements.
- Create milestones and dependency-aware tasks.

Stage 5: Development
- Create isolated work branches.
- Assign coding tasks to specialized agents.
- Implement features and tests.
- Require peer review for relevant changes.
- Track files changed and commits created.

Stage 6: Quality Assurance
- Run automated tests and applicable security checks.
- Validate acceptance criteria.
- Record reproducible defects.
- Send failed tasks back to the appropriate developer.
- Prevent failed quality gates from being marked as passed.

Stage 7: Release Preparation
- Prepare release notes, deployment instructions, and rollback plans.
- Verify build artifacts and test evidence.
- Identify unresolved issues and operational risks.
- Require human approval for production deployment.

Stage 8: Delivery and Retrospective
- Prepare a customer delivery package.
- Generate a project completion report.
- Compare planned and actual effort and costs.
- Record lessons learned after review.
- Update approved company knowledge.

Each stage must have explicit entry criteria, exit criteria, deliverables, and approval requirements.

## 14. SECURITY AND GOVERNANCE

Implement:
- Authentication and server-side authorization.
- Least-privilege permissions.
- Department, project, and resource-level access control.
- Secret management.
- Protection against prompt injection and malicious documents.
- Sandboxed code execution.
- Rate limits and resource budgets.
- Tool input validation.
- Audit logs for decisions and external actions.

- Data retention and deletion policies.

## 15. PERFORMANCE AND COST CONTROL

- Configurable concurrency limits.
- Model selection by task complexity.
- Caching where safe.
- Usage dashboards and cost alerts.

Never assume a model, integration, or tool is free or available without configuration.

## 17. ACCEPTANCE CRITERIA

A feature is complete only when:
- The implementation exists.
- Data persists correctly.
- Permissions are enforced server-side.
- Relevant automated tests pass.
- Errors are handled.
- Audit records exist where required.
- The UI reflects actual backend state.
- Documentation is updated.

Demonstrate an end-to-end workflow:
CEO creates a project → agents analyze requirements → a manager assigns tasks → a developer executes an authorized task → QA runs tests → a reviewer evaluates deliverables → the CEO approves the final result.

Do not mark a workflow complete if any required step is mocked or missing.
